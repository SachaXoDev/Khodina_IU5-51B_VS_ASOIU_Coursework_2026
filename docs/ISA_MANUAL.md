# Спецификация системы команд KOCTA-16 (IU5-RISC16)
## Руководство по архитектуре процессора (ISA Manual)

### 1. Архитектурный базис
Процессор **KOCTA-16** представляет собой 16-разрядную RISC-архитектуру с Гарвардской раздельной организацией памяти команд (ROM) и памяти данных (RAM/MMIO). Архитектура оптимизирована для встраиваемых управляющих систем, алгоритмической обработки массивов и интерактивных приложений реального времени с аппаратным ускорением.

- **Разрядность данных:** 16 бит.
- **Разрядность команд:** 16 бит (фиксированная длина).
- **Разрядность адреса памяти команд:** 8 бит (256 слов по 16 бит).
- **Разрядность адреса памяти данных:** 16 бит (адресуемое пространство 64K 16-битных слов).
- **Регистровый файл:** 16 регистров общего назначения (РОН) `R0`–`R15` по 16 бит.

---

### 2. Регистровый файл
| Регистр | Название | Назначение / Соглашение о вызовах |
| :--- | :--- | :--- |
| `R0` | ZERO | Аппаратный ноль (Hardwired Zero). Чтение всегда возвращает 0x0000, запись игнорируется. |
| `R1`–`R10` | GPR | Регистры общего назначения (вычисления, аргументы, локальные переменные). |
| `R11` | PTR / BASE | Указатель на структуры данных, базовый адрес MMIO. |
| `R12` | COORD / ACC | Координаты курсора / аккумулятор вспомогательных данных. |
| `R13` | SP | Указатель вершины стека (Stack Pointer). |
| `R14` | LR | Регистр возврата из подпрограмм (Link Register). |
| `R15` | FLAGS | Регистр флагов АЛУ (Z — Zero, N — Negative, C — Carry, V — Overflow). |

---

### 3. Карта памяти и MMIO
Память данных процессора имеет линейную 16-битную адресацию:

| Диапазон адресов | Область | Описание |
| :--- | :--- | :--- |
| `0x0000`–`0x000F` | RAM System | Системные переменные, аргументы задач (target, answer, move_count). |
| `0x0010`–`0x001F` | RAM Array | 16-элементный отсортированный массив для задачи бинарного поиска. |
| `0x0020`–`0x007F` | RAM Stack | Стек процессора для подпрограмм и RPN-калькулятора (растет вниз от `0x007F`). |
| `0x0080`–`0x0084` | RAM Board | Буфер строк 0..4 игрового поля Lights Out 5x5. |
| `0x0085`–`0x00FF` | RAM General | Общие пользовательские данные. |
| `0xFF00` | MMIO UART_TX | Порт вывода символа в консоль (запись ASCII-кода). |
| `0xFF01` | MMIO KEY_DATA | Порт ввода кода нажатой клавиши (чтение: ASCII/код направления). |
| `0xFF02` | MMIO KEY_STAT | Статус клавиатуры (1 = есть новый ввод, 0 = буфер пуст). |
| `0xFF10`–`0xFF14` | MMIO LED_ROW0..4 | 5x5 LED-матрица: строки 0..4 (биты [4:0] отображают состояние светодиодов). |
| `0xFF15` | MMIO CURSOR | Координаты курсора: биты [2:0] = X (0..4), биты [5:3] = Y (0..4). |
| `0xFF16` | MMIO MOVE_CNT | Счетчик совершенных игроком ходов. |
| `0xFF17` | MMIO GAME_STAT | Статус игры (0 = игра идет, 1 = победа: все огни погашены). |
| `0xFF20` | MMIO RPN_OUT | Регистр числового дисплея калькулятора. |
| `0xFFFE` | MMIO TIMER | Таймер системных тактов (read-only). |
| `0xFFFF` | MMIO HALT_SIM | Регистр останова симуляции (запись 1 завершает работу `$finish`). |

### 4. Форматы машинных команд
Все инструкции имеют разрядность 16 бит и делятся на 4 базовых формата:

```
Формат R (Регистр-Регистр):
 15       12 11        8 7         4 3         0
+-----------+-----------+-----------+-----------+
| Opcode[4] |   Rd[4]   |  Rs1[4]   |  Rs2[4]   |
+-----------+-----------+-----------+-----------+

Формат I (Непосредственный операнд / Константа):
 15       12 11        8 7                     0
+-----------+-----------+-----------------------+
| Opcode[4] |   Rd[4]   |       Imm8[8]         |
+-----------+-----------+-----------------------+

Формат M (Память: Load / Store с 4-битным смещением):
 15       12 11        8 7         4 3         0
+-----------+-----------+-----------+-----------+
| Opcode[4] |  Rd/Rs[4] |  Rs1[4]   | Offset[4] |
+-----------+-----------+-----------+-----------+

Формат B (Ветвление и переходы с 8-битным адресом):
 15       12 11        8 7                     0
+-----------+-----------+-----------------------+
| Opcode[4] |  Cond[4]  |      Target[8]        |
+-----------+-----------+-----------------------+

Формат S (Сдвиги с 4-битной константой величины сдвига):
 15       12 11        8 7         4 3         0
+-----------+-----------+-----------+-----------+
| Opcode[4] |   Rd[4]   |  Rs1[4]   |  Shift[4] |
+-----------+-----------+-----------+-----------+
```

### 5. Система команд (Таблица опкодов)

| Опкод | Мнемоника | Формат | Семантика | Описание |
| :---: | :--- | :---: | :--- | :--- |
| `0x0` | `NOP` | R | - | Холостая операция (`R0, R0, R0`) |
| `0x1` | `ADD Rd, Rs1, Rs2` | R | `Rd = Rs1 + Rs2` | Арифметическое сложение |
| `0x2` | `SUB Rd, Rs1, Rs2` | R | `Rd = Rs1 - Rs2` | Арифметическое вычитание |
| `0x3` | `AND Rd, Rs1, Rs2` | R | `Rd = Rs1 & Rs2` | Побитовое И |
| `0x4` | `OR Rd, Rs1, Rs2` | R | `Rd = Rs1 \| Rs2` | Побитовое ИЛИ |
| `0x5` | `XOR Rd, Rs1, Rs2` | R | `Rd = Rs1 ^ Rs2` | Побитовое исключающее ИЛИ |
| `0x6` | `CMP Rs1, Rs2` | R | `Flags = Rs1 - Rs2` | Сравнение операндов (установка флагов Z, N) |
| `0x7` | `LDI Rd, Imm8` | I | `Rd = {8'b0, Imm8}` | Загрузка младшего байта (0..255) |
| `0x8` | `LDH Rd, Imm8` | I | `Rd[15:8] = Imm8` | Загрузка старшего байта константы |
| `0x9` | `LOAD Rd, [Rs1 + imm4]` | M | `Rd = MEM[Rs1 + imm4]` | Чтение из памяти данных или MMIO |
| `0xA` | `STORE Rs, [Rs1 + imm4]` | M | `MEM[Rs1 + imm4] = Rs` | Запись в память данных или MMIO |
| `0xB` | `BRANCH Cond, Target` | B | `if (Cond) PC = Target` | Условные и безусловные переходы |
| `0xC` | `SHL Rd, Rs1, Imm4` | S | `Rd = Rs1 << Imm4` | Логический сдвиг влево на 0..15 бит |
| `0xD` | `SHR Rd, Rs1, Imm4` | S | `Rd = Rs1 >> Imm4` | Логический сдвиг вправо на 0..15 бит |
| `0xE` | `SYS Func, Imm8` | B | Системные функции | `0x0` = HALT (останов процессора) |
| `0xF` | `CROSS_XOR Rd, Rs1, Rs2`| R | Аппаратное ускорение | Применение крестовой маски Lights Out |

#### Условия переходов для команды `BRANCH` (Опкод `0xB`):
- `Cond = 0x0`: `JZ Target` / `BEQ Target` — переход, если `Z == 1` (равно).
- `Cond = 0x1`: `JNZ Target` / `BNE Target` — переход, если `Z == 0` (не равно).
- `Cond = 0x2`: `JLT Target` / `BLT Target` — переход, если `N == 1` (меньше).
- `Cond = 0x3`: `JGE Target` / `BGE Target` — переход, если `N == 0` (больше или равно).
- `Cond = 0x4`: `JMP Target` — безусловный прямой переход по адресу `Target`.
- `Cond = 0x5`: `CALL Target` — вызов подпрограммы: `R14 = PC + 1; PC = Target`.
- `Cond = 0x6`: `RET` — возврат из подпрограммы: `PC = R14`.

### 6. Аппаратное ускорение: Инструкция `CROSS_XOR` (Оценка «5»)
Инструкция `CROSS_XOR Rd, Rs1, Rs2` реализует специализированный аппаратный оператор наложения крестообразной XOR-маски для игрового поля Lights Out 5x5 за **1 машинный такт**.

#### Формат операндов:
- `Rs1` [4:0]: Текущее состояние строки игрового поля (5 бит: биты 0..4 соответствуют лампочкам 0..4).
- `Rs2`: Слово параметров клика:
  * `Rs2[2:0]`: Координата `X` клика (0..4).
  * `Rs2[5:3]`: Координата `Y` клика (0..4).
  * `Rs2[8:6]`: Индекс текущей обрабатываемой строки `Row` (0..4).
- `Rd` [4:0]: Выходное состояние строки после наложения маски.

#### Аппаратная логика (RTL combinational block):
```verilog
always @(*) begin
    wire [2:0] x = Rs2[2:0];
    wire [2:0] y = Rs2[5:3];
    wire [2:0] r = Rs2[8:6];
    reg [4:0] mask;

    mask = 5'b00000;
    if (r == y) begin
        // Центральная строка: инвертируется целевая ячейка и горизонтальные соседи
        mask[x] = 1'b1;
        if (x > 0) mask[x - 1] = 1'b1;
        if (x < 4) mask[x + 1] = 1'b1;
    end else if ((y > 0 && r == y - 1) || (y < 4 && r == y + 1)) begin
        // Соседняя строка сверху или снизу: инвертируется только ячейка по X
        mask[x] = 1'b1;
    end
    Rd = {11'b0, Rs1[4:0] ^ mask};
end
```
Благодаря этой инструкции обновление всего поля 5x5 требует всего 5 итераций простого цикла без сложных проверок условий выхода за границы поля.
